# 03 — Git and GitHub

## Git in one paragraph

Git is a **distributed version control system**. It stores the history of a
project as a graph of **commits** (snapshots). Each commit has a unique SHA-1
hash, an author, a message and a pointer to its parent commit(s).

## Core concepts

| Concept | Meaning |
|---------|---------|
| Repository (repo) | Folder + hidden `.git` database of history |
| Working tree | The files you currently see and edit |
| Staging area (index) | Files selected for the next commit (`git add`) |
| Commit | A saved snapshot (`git commit -m "..."`) |
| Branch | A movable pointer to a commit (`main`) |
| Remote | A copy of the repo elsewhere (`origin` = GitHub) |
| Clone | Copy a remote repo locally |
| Fork | **Your own server-side copy** of someone else's repo on GitHub |
| Push / Pull / Fetch | Send commits / get + merge / get only |
| SHA / hash | Unique commit ID; the short form is 7 characters |

## The commands from the README, explained

```bash
git init                         # create a new empty repo in this folder
git add .                        # stage everything
git commit -m "init: CI/CD demo setup"   # snapshot with a message
git branch -M main               # rename current branch to "main" (-M = force rename)
git remote add origin <url>      # name the GitHub URL "origin"
git push -u origin main          # upload; -u remembers origin/main as the default upstream
```

*Commit message style*: `init: ...` follows the **Conventional Commits** idea
(`feat:`, `fix:`, `docs:`, `chore:`), which makes history readable.

## How Jenkins uses Git

* `checkout scm` in the Jenkinsfile pulls the exact commit that triggered the build.
* `git rev-parse --short HEAD` returns the 7-character commit SHA, used in the image tag.
* `pollSCM('H/2 * * * *')` makes Jenkins ask Git "anything new?" every ~2 minutes.

### Polling vs webhooks

| | Polling (`pollSCM`) | Webhook |
|---|---|---|
| Who initiates | Jenkins asks repeatedly | GitHub calls Jenkins instantly |
| Latency | Up to the poll interval (~2 min) | Seconds |
| Network need | Jenkins needs outbound access only | GitHub must reach Jenkins (public URL/tunnel) |
| Good for | Local laptop demos (no public IP) | Real servers |

Because Jenkins runs on `localhost`, GitHub can't reach it, so polling is the
practical choice for this demo (the comment in the Jenkinsfile says so).

### Cron syntax `H/2 * * * *`

Five fields: `minute hour day-of-month month day-of-week`.
* `*/2 * * * *` would mean "every 2 minutes" exactly.
* **`H`** means *hash*: Jenkins picks a consistent but spread-out offset per job so
  hundreds of jobs don't all fire at minute 0. `H/2` = "every 2 minutes, at a
  hash-chosen offset".

## `.gitignore` explained

```
__pycache__/               Python bytecode cache folders
*.pyc                      Compiled Python files
.pytest_cache/             pytest's cache
kubeconfig                 Cluster credentials — SECRET, never commit
.env                       Local secrets
jenkins/.env               Jenkins secrets (Docker Hub token, admin password)
k8s/deployment.rendered.yaml   Generated by Jenkins at deploy time (sed output)
```

Rule of thumb: **never commit** secrets, generated files, caches or build outputs.

## `.gitignore` vs `.dockerignore`

| File | Controls |
|------|----------|
| `.gitignore` | What Git tracks/uploads to GitHub |
| `.dockerignore` | What is sent to Docker as **build context** |

They are separate; something can be committed to Git yet excluded from images
(e.g., `k8s/`, `Jenkinsfile`, `README.md`).

## Branching strategies (context)

* **Trunk-based**: everyone merges small changes to `main` often — fits CI/CD best.
* **GitFlow**: `develop`, `release`, `hotfix` branches — heavier.
* This project's job builds only `*/main` (`branch('*/${GIT_BRANCH:-main}')` in JCasC).

## Useful everyday Git commands

```bash
git status                 # what changed?
git diff                   # exact line changes
git log --oneline --graph  # compact history
git switch -c feature/x    # new branch
git pull --rebase          # update without merge commits
git restore <file>         # discard local edits to a file
git revert <sha>           # create a commit that undoes another (safe for shared branches)
```
